# 世界切片 · Codex 选题自动化

Updated: 2026-10-31 · Owner: 动动 · Lifecycle: 持续使用

每天北京时间 10:00 由独立自动化新建一次运行对话，标题为“世界切片 · YYYY-MM-DD 选题日报”，在该次对话直接展示正文。采集脚本只取公开数据，筛选、联网查证与成稿使用 Codex 本身的模型和工具。跨天上下文从本文及本机历史与反馈记录恢复。脚本不加载 `.env`，不读取模型密钥，不启动网页、PostgreSQL 或 Sub2API，不调用另一套 AI。

## 编辑目标

替动动挑出值得制作的历史人物、科普和社会现象视频选题。账号叫“世界切片”，简介为“一片一片看，用科学和故事，理解世界，也理解自己”。判断标准是观众此刻想弄懂的问题、解释后的认知回报、故事和能做出来的画面。重大事件先进入候选评估，再寻找其中的具体问题；新闻和热榜是发现入口。

### 动动的选题校准 · 2026-10-28

动动明确反馈：“iPad mini没有开扬声器孔，是怎么发出声音的”这条科普视频，比本轮给出的日食、蜘蛛、熔岩星球选题更有意思。这是本自动化的编辑偏好正例，优先级高于AI自行总结的趣味标准；没有相应播放数据，不写成已验证的传播规律。

优先发现：近期事件或熟悉事物中的一个具体反常细节，能立即让人产生疑问，再用清楚的原理与画面给出答案。这个例子的入口是新品发布，疑问来自“没有熟悉的扬声器孔，仍然能出声”，解释能落到实际发声结构。Apple官方已公开Acoustic Display及隐藏高音单元的安排，[原始公告](https://www.apple.com.cn/newsroom/2026/10/apple-gives-ipad-mini-its-biggest-update-ever/)。动动已经看过该题，后续将它当作已看样本，寻找其他问题。

同日按此方向重跑后，动动反馈“ok，这个比较符合我的品位了”。本批正向样本为：“蛟龙号下潜7000米，为什么要把电池泡在油里？”、“屏幕玻璃越光滑越好？苹果为什么偏要在上面刻纹路？”、“一张没有logo的图，Google怎么认出是自己画的？”。将这批作为实际认可的选题方向：熟悉物件或当下事件中的反常细节，问题能直接看懂，答案有具体原理，画面能展示解释过程。这是对整批方向的认可，未表达三题之间的喜好排序，也未要求自动加入待拍。后续寻找新的题材与细节，保留跨领域探索空间。

初筛时先判断：普通观众能否立刻看懂在问什么；是否有值得追问的细节；解释是否会改变对事件或眼前事物的理解；两三组画面能否讲清。科学论文、宏大背景、罕见纪录与知识量不能单独构成优先推荐理由。题材覆盖历史、自然、生活用品、交通、消费科技、金融安全、商业与公共社会事件；依据共同的选题价值比较。保留历史人物故事的空间，使用具体疑问、人物处境和可见细节评估，不将此次偏好变成固定故事模板或数码题配额。

### 动动的选题校准 · 2026-10-31

动动指出：“流程需要优化，最近币安被盗事件很大，我觉得这个应该进入选题的”。这次反馈要求重大事件进入候选比较，不能把iPad正例收窄成物件结构或物理科普偏好。人的处境、组织权限、交易流程和制度安排，同样能产生具体、可解释的观众疑问；不据此推断动动偏好所有币圈新闻，也不自动收藏或排期。

本次漏题同时暴露发现和筛选缺口：原六源116条线索没有币安事件，主动搜索又先限定科技、工程与自然方向。仅从采集包挑题、仅补搜已知领域，不能承担重大事件覆盖。改为先广扫近24—72小时国内外重大事件，再挖具体问题；题材探索继续保留。

以本事件为回归样例：币安2026年10月30日[第二次公告](https://www.binance.com/en/support/announcement/detail/d3306d9dca5243548c813b605e1d1751)确认热钱包异常提款、损失约63亿美元。可以切入“为什么有的币能冻结，有的不能”，用[Elliptic原始链上分析](https://www.elliptic.co/insights/binance-largest-hack-in-history/)和发行方规则解释。攻击归因与入口仍须以最新调查为准，不把初报的一台员工电脑、私钥泄露、朝鲜归因或区块链被破解当作已定结论。

比较候选时，同时看事件影响与时效、观众理解需求、解释回报、事实成熟度和画面成本。影响大且已有清楚切口的事件，应优先于只靠新奇细节或节日入口的弱候选；重大本身也不能替代查证。事实未清时缩小到已核实的问题，或列入暂缓。

每日主推 1 个，最多 2 个备选；不够就少推，全部不合适可零题。排除纯明星八卦、赛事、AI 融资和跑分。AI 相关线索只有能转成普通人关心的科学或社会问题时才入选。没有时效的历史和科普题可以明确写成长青题，不编造“今天突然值得拍”的理由。不要为了轮换题材强行选弱题。

先读 `My_life/video/world-of-why/README.md` 的账号、选题和视频目录，用于避免撞已做和正在制作的题；有必要再读对应内容包。未标注发布的作品不能说成已发布。不修改视频工作区，不自动生成脚本、媒体或执行发布。

## 每次运行

所有命令在 `apps/world-slice-daily/` 项目根执行。使用 Node.js 24.22.1 或更新版本。Windows 若 PATH 中 Node 太旧，优先 `$env:WORLD_SLICE_NODE`，再使用 `$env:USERPROFILE\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe`；其他机器使用符合版本的 `node`。不要调用 `scripts/update-daily.ps1`、旧 `run.ts` 或 `codex exec`。

1. `node modules/creator-daily/scripts/codex.ts context`：读取最近 14 份日报和全部待拍、跳过原因。同一天已有日报时，运行 `read` 并返回现有结果，除非动动要求重新选题、补入漏题或修订；普通定时重入不要再采集和重新生成。
2. `node modules/creator-daily/scripts/codex.ts collect`：读取 60s 新闻、抖音热榜、知乎热榜、AI HOT 精选、NASA、ScienceDaily，保存并返回 `.data/codex/signals-YYYY-MM-DD.json`。读取该文件中的信源状态和线索。当天缓存复用；只有明确需要刷新公开线索时才加 `--force`。单源失败继续使用其他源；六源全失败时报告具体失败，保留已有日报，下一次再尝试。
3. 六路信源是发现入口，不代表当天全貌。每天先用Codex原生搜索广扫近24—72小时国内外重大事件，第一轮不要加“科普、科学、工程、新品”等题材限定；综合报道用于发现，随后回到当事方、监管/执法机构、研究机构、原始调查或可靠史料核实。对重大失窃、安全事故、商业和规则变化等真实事件，先问观众最想弄懂什么，再判断能否解释清楚；之后继续补找产品、生活、自然或历史里的具体细节。搜索词由真实事件产生，不凭想象造前提。结合近期作品、历史日报和反馈比较候选。已收藏、已跳过、已看样本、近两周已推荐的同一事件默认不重推；跨来源同一事件合并，重推须说明实质新增进展。
4. 用 Codex 原生联网工具打开入选题的原始资料。科学题优先原始论文、研究机构或官方公告；历史题优先可靠史料、博物馆、学术机构与可核对的研究。核心事实没有查清就换题或暂缓。选题卡可以提出创作画面，不能把创作设想写成史实。核对发布日期和事件时间，来源前一天的内容按真实日期表达，热榜名次不能写成上升趋势。科普源新发文章可能重新介绍旧研究，必须核对原始论文或机构公告的年份；旧研究按长青题处理，不能称为今日新发现。
5. 成稿前做一次重大事件反查：本轮识别的相关重大事件是否逐一考虑，是否被容易画图的小题挤掉。将实际扫描来源、重大事件及“入选/暂缓/不选”理由简短保存到`.data/codex/coverage-YYYY-MM-DD.json`，供下一次漏题复盘；未识别到相关大事时保留搜索范围与结果，不凑事件数。入选线索如不在原包，先按下文“补充线索”导入，使用返回的真实id。用自身模型编写下述 JSON，UTF-8 保存到 `.data/codex/proposal-YYYY-MM-DD.json`。然后执行 `node modules/creator-daily/scripts/codex.ts publish --input .data/codex/proposal-YYYY-MM-DD.json`。保存失败先修正数据，不报告已经保存。
6. 执行 `node modules/creator-daily/scripts/codex.ts read` 读取成稿，在本次运行新建的对话直接给出日报正文，并链接 `.data/codex/YYYY-MM-DD.md`。不要只交文件路径、执行日志或状态通知。将一手来源链接放在相关事实旁边。

### 补充线索

将实际打开并核实的一手资料，以UTF-8数组保存到`.data/codex/supplement-YYYY-MM-DD.json`，每项字段：`source`（机构或资料名）、`title`（具体线索）、`summary`（资料支持的事实摘要）、`url`（原文HTTP/HTTPS链接）、`sourceDate`（原文真实日期YYYY-MM-DD，未知填null）、`publishedAt`（精确发布时间带时区，未知填null）、`kind`（news/science/trend/ai）。单次1—10项，不补造精确时间。

执行`node modules/creator-daily/scripts/codex.ts supplement --input .data/codex/supplement-YYYY-MM-DD.json`。它保留原包、按原文URL去重、分开保存发布时间与本轮观察时间，并返回可引用的真实id；`matches`包含本次输入对应的全部id，已有URL沿用原id。补充线索和固定信源使用同样的查证、去重与保存检查；保持已有引用校验。

### 用户要求当日补题或修订

先保留当日原proposal与阅读版到`.data/codex/revisions/YYYY-MM-DD/`，文件名带修订前的时间标记。复用现有采集包；新资料通过`supplement --input`追加，不能用强制重采集覆盖已补入的资料。修改当日proposal，保留仍成立的原候选，按新比较结果排序；使用`publish --force --input ...`保存并`read`回读。核对其他日期、反馈记录及保留题的id不变。用户指出值得进入候选，不自动等同于加入待拍。公开范围的流程说明与自动化提示词一并更新，运行数据继续留在本机。

## 成稿契约

```json
{
  "date": "北京时间当天 YYYY-MM-DD",
  "lead": "一句今天优先拍什么以及为什么",
  "ideas": [{
    "signalIds": ["本次线索文件中真实存在的 id"],
    "bucket": "today",
    "title": "8—65 字的完整候选标题",
    "whyNow": "为什么值得拍；长青题直接讲题材价值",
    "angle": "至少 12 字，替观众回答的一个具体问题",
    "hook": "一句能直接开口的候选开场",
    "visuals": ["第一组能做出来的画面", "第二组画面"],
    "effort": "轻量",
    "window": "具体制作窗口或长青题",
    "verify": ["开拍前仍须补齐的具体次要细节；没有就空数组"],
    "evidence": [{"title": "实际打开过的原始资料标题", "url": "https://真实网址", "fact": "该资料直接支持的具体事实"}],
    "updateReason": "只有重推旧题时填写可核对的新增进展；其他留空"
  }],
  "watch": [{"signalId": "本次线索真实 id", "reason": "具体暂缓原因；无必要就空数组"}]
}
```

`ideas` 为 0—3 项，顺序就是主推、备选 1、备选 2；`bucket` 为 `today` / `prepare` / `evergreen`，`prepare` 必须有明确的未来安排。`effort` 为 `轻量` / `常规` / `较重`；`visuals` 为 2—3 项；`verify` 最多 4 项；`evidence` 为 1—4 项；`watch` 最多 3 项。各字段简短、具体、写完整，不硬凑核实项。

报告保存到 `.data/codex/state.json`（历史与反馈权威源）和 `.data/codex/YYYY-MM-DD.md`（可重新生成的阅读版）。这些是本机私有运行数据，不进 Git。日报与选择记录持续保留，原始线索按日期保存；不要自动删除用户数据。原网页数据库保留，旧数据以只读导出导入，不依赖它参与日常运行。

## 在聊天里处理取舍

动动说“第二题加入待拍”“这题跳过，因为……”时，先用 `context` 定位对应日期和标题的真实 id；必要时读取 `state.json`，不能猜 id 或把新日报的序号套到旧日报。执行：

```text
node modules/creator-daily/scripts/codex.ts decide --id 真实id --decision saved --reason "动动实际表达的理由"
node modules/creator-daily/scripts/codex.ts decide --id 真实id --decision dismissed --reason "动动实际表达的理由"
node modules/creator-daily/scripts/codex.ts decide --id 真实id --decision new --reason "动动要求撤销"
```

没有给理由就省略 `--reason`，不编造偏好。只有动动明确挑选、跳过或撤销才改状态。讨论和追问不自动等同于收藏或排除；“以后少推这种”先记录这次被排除的具体题与原话，后续据此判断相似题，不扩成未经表达的永久禁令。写入后回读 `context` 核对。

## 切换与验收

必要验收：六路公开源真实采集；数据库和模型配置不可用时入口可用；不存在引用、重复题和无证据稿拒绝保存；已有反馈导入不覆盖新反馈；当天缓存、日报阅读和收藏不触发另一套模型。测试在 workspace `_tmp/` 创建隔离数据并自动回收，不写生产状态。
